# 加密资产月度专业调研报告

支持多资产。构建时用 `--asset` 指定，资产档案登记在 `build.py` 的 `PROFILES` 字典里。

## 资产间的框架差异（SOL 接入时实测得出）

约六成结构可复用，四成必须换：

| BTC 章节 | SOL 对应 |
|---|---|
| 减半周期 | ❌ → **通胀递减与销毁机制**，且 SOL 的通胀**可被治理投票修改** |
| 算力 / 矿工经济 | ❌ PoS 无挖矿 → **质押率与验证者经济** |
| 数字黄金叙事 | ❌ → **高性能应用执行层** |
| AI 多维影响 | ⚠️ 降级并入生态数据 |
| 上市公司储备 | ✅ 保留，SOL 渗透率约为 BTC 一半 |
| — | ➕ **网络稳定性与宕机史** |
| — | ➕ **生态数据**（TVL / DEX / 稳定币 / RWA） |
| — | ➕ **治理投票** |
| — | ➕ **与 ETH 的 L1 竞争** |

**最根本的差异**：BTC 是货币资产，估值锚是稀缺性；SOL 是**生产性资产**，估值锚应是**网络收入**。
因此 SOL 的情景推导用「假设年化收入 × 假设收入倍数」，而非 BTC 用的「已实现价格 × MVRV」。
接入新资产时先问：**它靠什么产生价值？** 答案决定第 9 章的推导方法。

## ADA 接入实测结论（2026-08 首期已完成）

预研阶段的假设**多数被推翻**，记录如下供后续资产参考：

| 预研假设 | 实测结果 |
|------|------|
| 「市值高、链上使用率低」 | ✅ **成立且比预想极端**：市值 $80.4 亿，L1 月费 $38,275，8 月交易 64.6 万笔（SOL 的 1/8000） |
| 「估值问题与 SOL 相反，需要第三种框架」 | ✅ **成立**。BTC 靠稀缺性、SOL 靠网络收入，**ADA 两条都够不着**——收入法失效**不是因为收入低**，而是**分母在噪声量级**（两个口径差 2.7 倍）。改用相对市值 + 情景概率，**但必须声明其分辨率不足以判断「低估/高估」** |
| 「治理已进入 Voltaire 阶段」 | ✅ 成立，且**治理是本期核心章**（替代 BTC 版的「上市公司储备」主位——ADA 企业储备近乎为零，不足以支撑一章） |
| 「Hydra 是主要二层方案」 | ⚠️ 部分。Leios（L1 扩容）才是当前主线，Hydra 与 Midgard rollup 是配套 |
| 「总量上限 450 亿，货币政策固定」 | ✅ 成立。无减半、无销毁，每 epoch 释放 reserves 的 0.3%，通胀 1.47% |

**ADA 版相对 SOL 版的章节改动约三成**：

| SOL 章节 | ADA 对应 |
|---|---|
| 通胀销毁机制 | ⚠️ 改为**储备衰减与国库**（ADA 无销毁机制） |
| 网络稳定性与宕机史 | ❌ 不适用（ADA 无重大共识事故）→ 并入起源章的技术取舍 |
| 治理投票 | ⬆️ **升为独立核心章**（第 5 章），因为它是 ADA 当期的第一变量 |
| 上市公司储备 | ⬇️ 降级并入「机构通道与持有者结构」（渗透率近乎为零） |
| — | ➕ **基金会自身资产负债表**（最了解这条链的机构如何配置自己的钱，是有力的旁证） |

## 接入新资产的步骤

1. 在 `build.py` 的 `PROFILES` 加一条（symbol / name / short / accent / badge）
2. 建 `<asset>/professional/charts/` 目录
3. 按上表调整章节框架
4. 建该资产独立的 `thesis_scorecard.md`（**不与其他资产混记**）
5. **找到该协议的治理仓库并翻一遍**（TRX 期教训——最关键的分项数据在 GitHub issues 里，不在浏览器和聚合器里）
6. **先问「它的收入以什么计价」**——若以标的自身计价（TRX / BNB / HYPE 都是），
   估值结构必须做退化检验，否则价格会在等式两边约掉
7. **先查三个默认是否成立**（XIN 期教训）：流通量已知吗、价格是可用的测量吗、
   **代币持有人是剩余索取权人吗**（这一条要找到赋权文件，不能假设）
8. **把数据源报告的供应量与链上直读的 `TotalIssuance` 对一次**（DOT 期教训）——
   差一个数量级就说明数据源在测另一条链

> SOL 接入时暴露的硬编码共 **5 处**（标题、顶栏、侧栏、hero、徽章）+ 主题色，比原先估计的 2 处多。
> 现已全部集中到 `PROFILES`，接入第三个资产应该只需改那一处。

## 第 1 步：抓数据

用 WebSearch 覆盖这 7 类。**不要凭记忆写数字**——每个月都变，写错就是硬伤。

1. **价格与市场**：现价、距 ATH 回撤、市值、关键支撑阻力、恐惧贪婪指数
2. **ETF 资金流**：当月净流入/出、YTD 累计、总 AUM、IBIT / FBTC 分项
3. **宏观**：美联储主席立场与利率路径、CPI / PCE、10 年美债、DXY、油价、黄金、标普
4. **链上**：MVRV、MVRV Z-Score、STH-MVRV、SOPR、LTH-SOPR、已实现价格、LTH 已实现价格、交易所余额、Puell Multiple
5. **上市公司储备**：总持仓、Strategy / Metaplanet / MARA 等头部动向、**有没有人在卖**、mNAV
6. **监管**：CLARITY 法案进度与通过概率、SBR / ARMA、各国政策
7. **AI 相关**：矿工转 AI/HPC、AI Agent 支付（x402 / L402 / 闪电网络）、量子威胁、AI 诈骗

搜索时把年月写进 query（如 `Bitcoin ETF flows August 2026`），否则容易搜到旧数据。

### ⚠️ 硬规则：凡有公开 API 的指标，一律不用搜索摘要（ADA 首期实测得出）

ADA 2026-08 期用一手 API 推翻了**五处**广泛流传的媒体数字，**没有一处是靠「多找几篇报道」能发现的**：

| 媒体口径 | 一手数据 | 差异性质 |
|---|---|---|
| IOG 研究预算「遭 86.72% 反对否决」 | **74.94% 赞成通过，已拨款** | **结论完全相反** |
| TVL 高点「2025-08 的 $4.372 亿」 | 2024-12-07 的 **$7.21 亿** | 回撤 –87.6% vs –91.0% |
| 质押率「63%–70%」 | **56.4%–57.0%** | 疑似沿用 2021–23 年数据 |
| 国库「超过 10 亿美元」 | **$2.88 亿** | 对应旧价格 |
| 基金会「BTC 持仓上升 25%」 | 占比升至 25.5%，**持仓降 37.8%** | **方向相反** |

**两条必须遵守的规则**：

1. **多家媒体报道一致 ≠ 事实。** 它们很可能引用同一时点的同一份快照。
2. **治理类数据必须查最终状态**（`ratified_epoch` / `enacted_epoch`），**不得使用任何时点的得票率报道**。
   加密治理投票期跨多个 epoch，**大量票在后期涌入**，中途快照可以与最终结果完全相反。

**已验证可用的免费一手 API（无需 key）**：

```bash
# Cardano 链上：epoch 数据、治理动议最终状态、供应量、质押池
curl "https://api.koios.rest/api/v1/epoch_info?_epoch_no=653"
curl "https://api.koios.rest/api/v1/proposal_voting_summary?_proposal_id=<gov_action...>"
curl -G "https://api.koios.rest/api/v1/proposal_list" \
  --data-urlencode "proposal_type=eq.TreasuryWithdrawals" \
  --data-urlencode "select=proposal_id,proposed_epoch,enacted_epoch,expired_epoch,title:meta_json->body->>title"

# TVL / 费用 / 稳定币（defillama.com 网页被网络策略拦截，但 API 可用）
curl "https://api.llama.fi/v2/historicalChainTvl/Cardano"
curl "https://api.llama.fi/summary/fees/cardano?dataType=dailyFees"   # 只有 L1 链费
curl "https://api.llama.fi/overview/fees/cardano"                     # 生态合计（含应用层）
```

### ⚠️ 费用口径：L1 链费 ≠ 生态合计费用

DefiLlama 的 `summary/fees/<chain>` 返回的是 **L1 协议层费用**；`overview/fees/<chain>` 才是**含应用层的生态合计**。
ADA 首期实测：L1 30 天 $38,275，生态合计 $353,264，**相差 9.2 倍**。

**两者用途不同，不能混用**：

- **L1 费** → 衡量**代币的价值捕获**（这部分才流向持币人的奖励池与国库）
- **生态合计费** → 衡量**生态活跃度**（归各应用协议，不流向持币人）

把 L1 费称作「全网手续费」并用它论证「生态没人用」，是**口径偷换**——ADA 初稿就是这么写的。
这与 SOL 首期的教训同源：**网络毛收入 ≠ 持币人现金流。**

### ⚠️ 识别风险 ≠ 处理风险

ADA 初稿在附录里**自己**把「86.72%」标注为「仅搜索摘要、未打开一手投票记录」，
在记分卡里**自己**写了「这是本期最重要却核实等级最低的数字，下期必须补一手核实」——
**然后就把它写进了核心结论。**

**不允许把已知的高风险项推迟到「下期核实」。** 凡链上可查的事实，写作阶段就必须查链上。

### ⚠️ 一个「完美吻合」本应是警报（HYPE 期实测得出）

HYPE 首期的核心结论建立在「每月解锁 992 万枚」上，**而这个数字恰好等于「总分配 2.38 亿 ÷ 归属期 24 个月」**。

**这个吻合本应引起警觉——它说明该数字很可能是某人的机械平均，而不是实测值。初稿把它当成了印证。**

一手核实（The Block）证明：**团队明确表示「归属不是线性的」**，实际分发是 175 万（2025-11）、120 万（2026-01），
**初稿高估了 5.7–8.3 倍**，据此得出的「年化净稀释 49%」「期望价 –63%」全部作废。

**规则**：**任何来自二手的关键数字，先做一次「它是不是某个简单除法的结果」的检验。**
若是，就必须找到实测值再用。

### ⚠️ 标注了风险 ≠ 标注对了风险（HYPE 期）

HYPE 初稿在五处标注「992 万枚是二手数据」，并在记分卡把核实它列为第一优先。
**但推理审查指出：把 992 万换成任何值，初稿的 –63% 都不动；真正承重的是「2029 年流通量假设」，而它一个字的标注都没有。**

**ADA 期的教训是「识别风险 ≠ 处理风险」，HYPE 期更靠前一步：「标注了风险 ≠ 标注对了风险」。**

**做法**：**给出结论前，逐个输入做一次「把它换成合理区间的另一端，结论会不会变」的测试。会变的才是承重墙，才值得标注和核实。**

### ⚠️ 结论比过去更强硬时，要检查它凭什么更强硬（HYPE 期）

前五期都以「框架分辨率不支持方向性判断」收尾，HYPE 初稿第一次给出明确判断（–63%），理由是「算术差距足够大」。
**而那个差距本身就是错的。**

**规则**：**当某一期的结论强度明显高于过往时，把「凭什么这次可以更强硬」当作一个独立的检查项**——
它通常指向一个未被充分核实的输入。

### ⚠️ 横向对照必须先声明口径（ETH 期实测得出）

ETH 首期出过本系列**最不该出的一个错**：正文写「四个资产同源上涨，而 ETH 涨幅最大（+29.86%）」，
**而同一句话里就列着 SOL +37.4%**，第 8 章的对照表里也白纸黑字写着同一个数。

**根因是混用口径**：ETH 用的是 8/1→8/31 的**月度涨幅**，SOL 用的是 CoinGecko 的 **`chg30d`（近 30 天）**。
统一后：**SOL +39.68% > ETH +29.86% > BTC +23.62% > ADA +14.65%**。

**两条规则**：

1. **同一张表内不得混用时间窗口。** 月度涨幅（月初→月末）与「近 30 天」是两个不同的数，不可互换。
2. **横向对照必须在表头或脚注写明口径**，例如「统一按 8/1→8/31 口径，CoinGecko 一手」。

> **ADA 期的错误是被外部媒体误导，ETH 期的错误是没看自己的表。** 后者更不该发生。
> **一手数据抓得再全，不去交叉核对自己写下的内容，一样会出错。**

### ⚠️ 「同比」必须是真同比

ETH 初稿写「L1 费用同比 –40.4%」，用的是**最近 30 天年化 vs 过去 12 个月总额**——
这不是同比，它比较的是当前月度运行率与**包含该 30 天在内**的 12 个月月均值。

**真同比要拿同月对同月**。改用 DefiLlama 月度序列后：2026-08 $1,038 万 vs 2025-08 $3,959 万 = **–73.8%**。
**修正后结论比初稿更强**——但方法必须对，否则一个正确的结论建立在错误的算法上，下期无法复现。

```bash
# 拿月度序列算真同比（DefiLlama 日度数据按月聚合）
curl -s "https://api.llama.fi/summary/fees/<chain>?dataType=dailyFees" | python3 -c "
import json,sys,datetime
from collections import defaultdict
d=json.load(sys.stdin); m=defaultdict(float)
for t,v in d['totalDataChart']:
    m[datetime.datetime.fromtimestamp(t,datetime.UTC).strftime('%Y-%m')]+=v
for k in sorted(m)[-16:]: print(k, round(m[k]))
"
```

### ⚠️ 声明了偏向，就要在评分里执行

ETH 期在附录准确声明了「空头论据来自一手 API、多头论据几乎全是二手转述，读者应据此调整信任度」，
**但 7.1 的多头星级没有做任何折扣**——等于把修正动作外包给读者。

**规则**：**多空评分表的星级必须编码证据等级。** 一条论据若全部建立在二手转述上，
**不得给到五星**，且需在说明栏写明「本报告未取得一手来源」。ETH 期据此下调了四条多头论据。

### ⚠️ 框架变复杂后的新错误类型：模型内部的重复计算（BNB 期）

**前四期的错误都是「数据或口径出错」。BNB 期最严重的错误是「两处单独看都正确的计算，组合起来成了错误」。**

具体：报告的目标价 = 参照市值 ÷ **缩减后的流通量**。销毁效应因此**已经全额包含在目标价里**（贡献 +15.86%）。
而报告又把总回报写成「资本利得 + 回购收益率 4.2%–4.56%」**两项相加**——**重复计入了约 16 个百分点**。

**两条规则**：

1. **任何「收益率」在与「价格目标」并列前，先问：这个效应是不是已经在目标价的分母或分子里了？**
   若目标价已按缩减/增发后的供应量折算，**供应变化的收益就不能再单列**。
2. **区分「市值层」与「单币层」。** 正确做法是相乘不是相加：
   单币层回报 = (1 + 市值层回报) × (当前流通量 ÷ 未来流通量) − 1。

**另一条相关的**：**只能通过价格实现的收益，不能与债券票息并列比较。**
BNB 的销毁没有现金流出、持有者也没有剩余索取权——**「价格不动仍有收益」这个说法在它身上不成立**（币数没变，美元价值没变）。

### ⚠️ 声称「低波动」前先把波动率算出来

BNB 期初稿写「波动性是五个资产里最低的」，依据是「近 1 年跌幅最小」。
**跌幅是收益率，不是波动率。** 实际计算后：**BNB 年化波动率 52.6%，高于 BTC 的 44.2%，排第二**——初稿的说法是错的。
**但 beta（相对 BTC）0.921 确实是五个里唯一低于 1 的**，低 beta 的论断在正确的统计量上成立。

```python
# 20 行就能算，不要用跌幅代替
rets = [log(px[i]/px[i-1]) for i in 1..n]
ann_vol = stdev(rets) * sqrt(365)
beta = cov(rets_asset, rets_btc) / var(rets_btc)
```

### ⚠️ 规范性判断必须给门槛

「折价不充分」「估值偏贵」这类判断**如果不给一个数字门槛，就既不能被同意也不能被反驳**。
BNB 期的「折价不充分」被重复了七处却没有门槛，审查后补为「**要求至少 300bp 溢价**」——
**这样读者可以说「我认为 100bp 就够」，判断才成为可讨论的。**

### ⚠️ 撤回一个结论，和让撤回生效，是两件事（ZEC 期，可机械化）

ZEC 期在正文里干净地撤回了一个退化指标（「市值/屏蔽池价值 3.47 倍」）并给出了证明，
**而它在一页速览、附录和配套速查文件里活得好好的——一共 9 处。**
**更糟的是审查记录那一节的「处理」列全打了 ✅，等于记录本身在说谎。**

> **固定动作**：**把审查记录里的每一条「X → Y」当成一份 grep 清单，
> 对旧值 X 在全部产物里搜一遍**（正文 `.md`、配套速查 `.md`、记分卡、以及生成的 `.html`）。
> **这比极值 min/max 检查命中率更高，且同样可机械化。**
>
> **为什么会漏**：修订时的注意力在「把正文改对」，
> **而摘要与配套件是「已经写完的东西」，不在修订的视野里。**

### ⚠️ 不判别的证据不能用来表态（ZEC 期）

ZEC 期在「这次流出是信任冲击还是巨鲸腾挪」这个问题上倾向了前者，
**理由是「价格同期 –37.2%，说明反应是广泛的」。**

**这条理由对两个假设的似然比是 1**：价格由交易所边际成交决定，与「谁在去屏蔽」正交——
**一个大户去屏蔽 + 几千个交易者抛售，同样产生 –37.2%。**
**而报告在别处还声明过价格不可解读**（R² 只有 19.9%、一年 12 天单日 >20%）。

> **规则**：**表态之前先问「这条证据在对立假设为真的世界里，会不会同样出现」。**
> **会，就不能用它表态。**
>
> **ZEC 期的正确做法是补一次判别性测量**——逐块采样测时间集中度，
> **结果直接改变了结论**（单个 4.1 小时窗口占 25.7%，措辞从「信任冲击」改为中性）。
> **而那个测量所需的方法，报告在另一节已经演示过了。**
> **「已尝试并失败」如果只试了一个字段、一个供应商，撑不起「本报告没有答案」。**

### ⚠️ 利益相关声明必须对准真正的敞口（ZEC 期）

ZEC 期声明的防守面是「不评价 AI 辅助审计的价值」，**字面上做到了，全文一句没有。**
**但这个利益冲突最可能的表达方式不是「说 AI 审计好」，
而是抬高该事件在报告结构中的权重与因果归属。**

审查找到三处痕迹：把「技术执行」的计时起点设在**发现日**而非**引入日**
（从引入日算是「带着伪造漏洞跑了四年」）；把价格跌幅列进「链上测到的后果」而从未做基率比较；
声明本身没有让任何一颗星、任何一个概率发生改变。

> **规则**：**声明一个防守面，会制造「已经处理过了」的错觉，而错觉的代价是真正的敞口没人看。**
> **利益相关声明必须附三条具体动作，而不是一句「读者请自行折扣」。**

### ⚠️ 别用「自查 vs 外部审查」的命中率下结论（ZEC 期）

ZEC 期观察到「自查抓到的四处全在历史清单上，而外部审查抓到的三条都不在」，
并据此写下「自查只能抓清单上的东西」。**这个结论是流程构造出来的**：

- **自查在前、外部在后**——清单上的错误已被自查清干净，外部不可能再找到清单上的东西；
- **「按清单找、找到清单项」近乎同义反复**；
- **同一张表还自己推翻了它**：外部审查的第一条被报告归类为「ETH 期教训的复现」，等于承认它也在清单上。

> **可以说的只有**：**清单条目若写成箴言（「要交叉核对自己写下的内容」），机械自查抓不到；
> 把箴言翻译成可执行检查就能抓到。**
> **这两条结论指向相反的资源分配——买更多外部审查 vs 重写清单条目。别选错。**

### ⚠️ 极值断言必须回到数据表用 min/max 复算（ZEC 期实测得出）

ZEC 期把屏蔽占比的「谷底」写成 26.09%，**而正确答案 25.49% 就在同一张表往下两行。**
**领域审查一眼看出；作者没发现，第 1 层脚本也不检查这个。**

> **规则**：**凡文中出现「峰值 / 谷底 / 最高 / 最低 / 最大 / 最小」这类极值断言，
> 都必须回到对应的数据表用 min/max 复算一次。**
>
> **它的性质值得注意**：这类错误**不需要任何外部知识就能被发现**，
> 却同时逃过了作者和脚本——**因为写的人和检查的人是同一个，而脚本没有这条规则。**

**已加进 `tools/verify_report.py`，但它是「只列不判」的**：

脚本会在末尾列出全文所有极值断言，供人工复核，**不做自动判定。**

> ⚠️ **这个设计是试错之后的结论，值得记下来。**
> **自动判定试了三种作用域——同段、同表、同列——假阳性都压不下去。**
> **根因是这些报告里既有「资产做行」也有「指标做行」的转置表，通用解析器分辨不了
> 「31.01% 的屏蔽占比」和「152.2% 的波动率」不可比。**
>
> **而假阳性会训练人忽略告警，比没有检查更糟**——这一点 `_dalin` 在全局偏好里写过：
> **「对一个观察结果提议『要不要斟酌一下』是噪音，而且会训练我在真正要紧的时候也忽略这个提议。」**
> **所以宁可只列不判：零假阳性，且仍然把注意力精确导向该复核的那几句。**

### ⚠️ 一个间隔推不出一个周期（ZEC 期）

ZEC 期观测到开发基金 `lockbox` 在区块 3,146,400 被单块清空，
而它距池启动（2,726,400）恰好 **420,000 区块**——报告据此推断了「420,000 的拨付周期」
并给出「下次在区块 3,566,400」的精确预测。

**领域审查指出：这只基于一次观测，且与对应的协议规定（一次性拨付）冲突。**

> **规则**：**「周期」是一个需要至少两个间隔才能支持的断言。**
> **一个漂亮的整数（420,000）会让人误以为发现了规律**——
> **这与 HYPE 期「完美吻合本应是警报」同源：整数本身不是证据。**

### ⚠️ 「没有收入」与「持币人没有索取权」是两回事（ZEC 期）

ZEC 期为了论证不给目标价，写了「ZEC 没有收入」。
**而 PoW 链的手续费是真实收入，只是按协议归矿工。**

> **规则**：**不给目标价的理由必须是「缺乏可信的估值模型与参数」，
> 而不是否认一个确实存在的现金流。**
> **把「我拿不到」说成「它不存在」，是一个事实错误，而且它会让报告显得比实际更有把握。**

### ⚠️ 隐私资产会让通用数据源静默失效（ZEC 期，第六个口径坑）

Blockchair 报告的 ZEC `circulation` 是**负数**（–529.98 万枚），
`inflation_24h` 也是负的——**它的透明 UTXO 模型处理不了屏蔽池。**

> **前五个口径坑**：ADA 的 L1 费 ≠ 生态合计、ETH 的 blob ≠ L2 全部支出、
> TRX 的「费用」被定义成「销毁」、XIN 的只查英文版、DOT 的测错链。
> **ZEC 期的成因不同：是标的的技术特性让数据商的模型不适用，不是数据商的疏忽。**
>
> **可用的替代**：Zcash 节点的 `valuePools` 与 `chainSupply` 是链上记账项，
> Blockchair 的 `raw/block` 端点会原样转发。**六个池的合计必须恰好等于 `chainSupply`——
> 这是一个免费的内部一致性检验，ZEC 期用它排除了「快照不一致」的质疑。**

### ⚠️ 先确认数据源在测哪条链（DOT 期实测得出，第五个口径坑）

前四个口径坑是**指标选错了**（ADA 的 L1 费 ≠ 生态合计、ETH 的 blob ≠ L2 全部支出、
TRX 的「费用」被定义成「销毁」、XIN 的只查了英文版）。
**DOT 期是第五个，而且性质不同：标的选错了。**

Polkadot 于 2025-11-04 把余额、质押、治理整体迁到 Asset Hub。
**中继链上只剩 0.014% 的 DOT，而 DefiLlama 与 Subscan 的默认 `Polkadot` 端点仍在测中继链。**
**DefiLlama 显示的「2025-11 费用骤降 92%」，塌方的月份正是迁移完成的月份。**

> **规则**：**当一条链把核心功能迁到另一条链上时，所有按链名索引的数据源都会静默地继续返回旧链的数据。**
> **它不报错，它返回一个看起来正常的小数字。**
>
> **接入新资产时的检查动作**：**把数据源报告的供应量与链上直读的 `TotalIssuance` 对一次。**
> 差一个数量级就说明测错了地方。DOT 期这一步只花了两次 RPC 调用。

**自己算存储键的方法**（需要时用，不必依赖第三方索引）：
`twox128(pallet) + twox128(item)`，**并用两个已知哈希自检**——
`twox128("System") = 26aa394eea5630e07c48ae0c9558cef7`、
`twox128("Number") = 02a5c1b19ab7a04f536c519aca4983ac`。
**DOT 期正是靠这个自检发现「我记忆里的 TotalIssuance 哈希是错的」。**

### ⚠️ 检查有没有两条论据在描述同一个机制的两面（DOT 期，本期最重要的一条）

DOT 期初稿一边给多头论据「21 亿供应上限已确立」**五星**，
一边把空头论据「每年 3.29% 稀释」写成**永续常数**（「不像大多数风险需要触发条件，每年都会发生」）。

**而如果上限为真，剩余可增发就只有 3.982 亿枚 = 当前供应的 23.4%，约 7 年触顶，且速率在衰减。**
**稀释是一个有限总量，不是永久年费——两者对长期持有决策的含义完全不同。**

> **规则**：**多空表做完之后加一步——检查有没有两条论据在描述同一个机制的两面。**
> **若有，必须让其中一条去约束另一条的量级，并把校正结果写进结论。**
> **本系列做了十期才发现这一步，而它抓到的是当期最强的两条论据。**

### ⚠️ 盈亏平衡反推 > 区间敏感性（DOT 期）

DOT 期初稿对 coretime 单价做了 100 倍的区间检验，宣布「区间两端结论相同」。
**而被变动的是报告亲手解码、有两处自洽检查的那个量；
完全没被变动的是 Asset Hub 的费用收入——报告自己标为「❌ 未获取」的那个量。**

> **对已知的做敏感性、对未知的不做，然后宣布区间两端结论相同——
> 这不是区间检验，是把不确定性挪到了区间外面。**
>
> **正确形式是盈亏平衡反推，它一次封住所有未测项**：
> 「要让结论翻转，未测项需要达到多大？」
> DOT 期的答案是「**未测的 Asset Hub 费用收入需要是已测总和的约 4,000 倍**」——
> **这句话比任何区间都强，因为它对未知项没有留口子。**

### ⚠️ 嵌套窗口不是多次验证（DOT 期）

DOT 期初稿用四个**共享同一终点、且互相嵌套**的窗口测通胀，
报「一致到小数点后两位、离散度 0.008pp」，并称之为「做过的最干净的一次测量」。

**两个问题**：
① **短窗口是长窗口的子集，离散度被机械压缩**——改用互不重叠区间后真实离散度是 0.30pp，差 37 倍；
② **四个窗口共享终点，若终点读数有偏会同向同幅偏移**，一致性检查对最该防的错误零灵敏度。

> **规则**：**做时序差分测量时用互不重叠的区间；共享端点的「一致性」不构成独立验证。**
> **真正的独立性检验是换一个数据端点（第二个 RPC 节点）复读同一区块。**
>
> **顺带**：DOT 期改用互不重叠区间之后，**看到了初稿看不到的东西**——
> 阶梯下调前 7.25%、下调后 3.44%。**一个更严谨的方法给出了更强的结论，而不是更弱的。**

### ⚠️ 写第一章之前先问：三个默认还成立吗（XIN 期实测得出）

前八期都默认了三件事：**价格是可用的测量、流通量是已知的、代币持有人是剩余索取权人**。
**XIN 同时打破了这三个默认**，而初稿是在写到第 4 章时才发现的。

**接入新资产的第一个动作，应当是逐条检查这三项**：

| 检查 | 怎么查 | XIN 期的答案 |
|---|---|---|
| 流通量已知吗 | 数据商的 `circulating_supply` 字段 + 链上持有人分布 | ❌ 字段为 0；前 50 名持 98.88% |
| 价格是可用的测量吗 | **日成交额中位数**（不是均值）+ 单日 >20% 波动的天数 | ❌ 中位数 $10,878；一年 17 天 |
| **代币持有人是剩余索取权人吗** | **找到赋予该权利的文件** | ❌ **没找到——而初稿仍然假设了它** |

### ⚠️ 「排在债务之后」是一个需要文件支持的主张，不是一个自然假设（XIN 期，本期最严重的错误）

XIN 期初稿写「营业利润 → 还债 → 剩下的才轮到股东与代币持有人」，
**把一个网络代币放进了公司的资本结构。**

**没有任何文件赋予 XIN 对 Mixin 公司利润或清算剩余的请求权。**
真实的传导是**经营层面**的（债务占用现金流 → 削弱对网络的投入 → 影响代币价值），
**而它比法律次序弱得多，且可以被业务增长抵消。**

> **两个层面必须分清**：
> **法律次序**意味着「债务不清偿，代币结构上一文不值」；
> **经营传导**只意味着「债务负担越重，网络越可能投入不足」。
>
> **更值得记的是初稿怎么犯的**：**它在第 11 章写过「XIN 的股权地位没查到定义」，
> 然后在第 6 章当这个空白不存在。**
> **章节之间的自洽检查，和单章内的严谨是两件事**——ADA 期「识别风险 ≠ 处理风险」的同一形态。

### ⚠️ 「不可定价」是一个需要被证明的结论，而证明它的方式不是展示工作量（XIN 期）

XIN 期初稿用「三层同时失效」支撑「不给目标价」，并在全文五处强调「本报告为此付出了代价」。

**两处都错**：

1. **三层不独立。** 供应集中与报价噪声是同一事实的因果两端；
   **而报价噪声根本不是定价障碍**——**市价是估值的比较对象，不是估值的输入。**
   噪声的市价意味着不能信任市场，不意味着算不出价值。**初稿把「不可交易」写成了「不可定价」。**
   正确结构是「**一个充分条件 + 若干加重情节**」，并说明**加重情节解决了也不够、充分条件解决了就够**。
2. **列举工作量是诉诸努力。** 初稿列的五项工作**全部在为「不可定价」取证，没有一项是一次崩掉的估值**。
   **要拿到「我试过但算不出来」的资格，必须展示一次失败的定价尝试，而不是更多支持「算不出来」的证据。**

**修正后的标准写法**：

| 路径 | 崩在哪一步 | **崩之前拿到了什么** |
|---|---|---|
| 倍数法 | 分母口径 | 可算的比值（FDV/TVL、换手率） |
| 相对市值法 | 无可比对象 | 无 |
| 剩余索取权法 | 业务价值那一侧 | **债务的界** |

**再加一节反推**：**当前价格要成立，什么必须为真？** 这一步不需要任何不可得的输入。

### ⚠️ 用「精度不足」丢弃一个在全区间内都成立的界（XIN 期）

XIN 期初稿算出「剩余债务 $5,200 万–$7,700 万」后**把它扔了**，理由是输入全为二手。
**但那是对「求界」的问题施加了「求点估计」的精度标准**——
该区间对应 FDV 的 **0.76–1.13 倍**，**两端的定性结论完全相同**。

> **规则**：**丢弃一个估计之前，先检查它的不确定性区间两端是否指向不同结论。
> 若不指向不同结论，它就是可用的，只是不能当点估计用。**

### ⚠️ beta 必须和 R² 一起报（XIN 期）

XIN 的 beta 是 0.63，TRX 是 0.247——**单看 beta，XIN 更「正常」**。
**而 XIN 的 R² 只有 2.4%，TRX 是 16.8%。XIN 那个 beta 是拟合噪声得到的数字。**

**「低 beta」有两种来源：真的不相关，和测不出来。只报 beta 会把两者写成同一件事。**

**回填成本几乎为零**：`R² =（β × σ_BTC ÷ σ_资产）²`，
且可以用一个实测过 R² 的资产验证这个恒等式（XIN：推算 2.5% vs 实测 2.4%）。
**前八期报了八次 beta 一次 R² 都没报，全部可以一行代数补上。**

### ⚠️ 「官方没有披露」必须查过所有语言版本才能下结论（XIN 期，发布后才发现）

XIN 期初稿写「官方支持文档只写了清偿次序，**没有写金额和期限**」，
据此把两个关键数字全部标为二手，**还在记分卡里认定相关论点不满足门槛 10**。

**发布当天就被推翻**：Mixin 支持站的**中文版**有一篇《【公告】MDT 债务偿还计划说明》，
**「2300 万美元」与「2026 年 9 月 23 日前」逐字写在里面。本报告只查了 `/en/`，没查 `/zh/`。**

> **规则**：**「查了官方文档」这句话默认暗示查全了。**
> **多语言站点的不同语言版本内容可以不同**——尤其是面向特定地区用户的公告。
> **下「官方未披露」这个结论之前，至少要试 `/en/` 与 `/zh/` 两个前缀。**
>
> **附带的连锁后果值得记**：这一处漏查污染了三个下游判断——
> 来源等级表、记分卡的门槛合规判定、**以及一条论点的概率赋值**
> （悲观的一半理由是「承诺只有二手来源」）。
> **一个概率赋值如果依赖「我没找到证据」，就必须先确认「我真的找过了」。**

### ⚠️ 「已拉取全部记录」必须是检查过的结论（XIN 期）

XIN 期初稿写「本报告拉取了…全部 XIN 转账记录…无分页，即为全部历史」——
**而那只是接口返回的第一页。** 分页拉全后：

- SafeProxy #3 的记录从 **6 笔变成 32 笔**
- 金库近 12 个月流出从 **5,000 枚更正为 15,001 枚（3 倍）**
- 新增了**一整段 2024 年的历史，初稿完全没看到**，且它证明资金流向是**双向**的

**验证是否拉全的方法很便宜**：**IN 合计 − OUT 合计 应当等于当前余额。**
XIN 期拉全后 252,627.41 − 167,627.41 = 85,000，与余额完全吻合。

### ⚠️ 地址集中 ≠ 锁仓（XIN 期）

初稿把前 50 名一律当作「不可交易」，据此估出「实际可交易 1–2 万枚」，
**并用它否定了一整套估值方法。**

**逐个查询对手方后发现，第 7 大持有人是一个 DEX 流动性池**——它正在交易。

> **规则**：**在用「集中度」论证「流通盘小」之前，必须逐个查大额地址的转账对手方。**
> **可辩护的做法是给上界**（总供应 − 已证明锁定的部分），
> **而不是给一个未标注推导的中心值**——**上界比中心值更适合承担否定性论证。**

### ⚠️ 查询窗口长度会改变返回值（XIN 期，影响全系列）

CoinGecko 的 `market_chart/range` 接口，**同一个日期在不同长度的查询窗口下返回不同的值**
（窗口短则返回小时级数据，"2026-08-01" 取到的是当日第一个小时点而非日线）。

XIN 期实测：同一组资产、同一个 8 月，短窗口给出 BTC +25.13%、TRX +1.62%，
长窗口给出 BTC +23.62%、TRX +3.14%——**与前期已发布的表格对不上。**

> **规则**：**跨期可比的表格必须用同一个查询窗口，并把窗口写进口径声明。**

### ⚠️ 做了敏感性分析 ≠ 做对了敏感性分析（TRX 期实测得出，本系列最贵的一条）

TRX 初稿执行了 HYPE 期的教训（「把每个输入换成合理区间的另一端」），
**做完之后写出了全篇的核心判断：「决定 TRX 估值的是 27 个超级代表，估值倍数只值 0.9 个百分点」。**

**那个分析是错的，而且错法极其隐蔽**：初稿对「收费率」取了**区间下沿**（悲观值），
对「估值倍数」取了**概率加权均值**。**用均值替换一个分布，当然不动。**
按区间端点重算，倍数的摆幅是 **54.6 个百分点**，而收费率只有 21.2——**排序完全相反。**

> **任何两个线性因子的重要性之比，等于作者给它们选的扰动宽度之比。
> 这个比值里可以一点标的信息都没有。**

**两条规则**：

1. **敏感性表的每一行必须注明「该输入被推到了它区间的哪一端」**，且每个输入都要给低端和高端两行。
2. **一个错误的敏感性分析比没有敏感性分析更危险**，因为它自带一层严谨的外观，
   会让作者比不做时更自信。**当敏感性的结论让你觉得「那就不用管这个变量了」时，先检查扰动宽度。**

### ⚠️ 估值结构的退化检验：价格会不会在等式两边约掉

TRX 初稿用「市值 = 年化销毁额(USD) × 倍数」，再「价格 = 市值 ÷ 流通量」。
两式连立后 **价格被完全约掉**，只剩「流通量 = 年化销毁量(TRX) × 倍数」——**不产生任何价格信息。**

**根因是口径混用**：分母用**标的计价**的流通量，分子用**美元计价**的收入乘倍数，
而这两者之间恰好差一个标的价格。**任何「销毁/收入以标的计价、再折成美元」的资产都有这个陷阱**
（TRX、BNB、HYPE 都是）。

**两个必做的检查**：

1. **把情景反解回物理量。** TRX 初稿的悲观情景反解后隐含**销毁上涨 43%**——
   与它全部空头论据方向相反。**三个情景不是同一机制的三种强度，而是三个互不相容的世界。**
2. **估值锚的分子分母都不能含标的价格。** TRX 期最终改用「市值 ÷ 稳定币存量」，
   并用 25 个月的历史区间给它定标——**经验区间比自己编的倍数可辩护得多。**

### ⚠️ 字段名不等于字段含义（TRX 期）

TRX 初稿用 Tronscan 的 `freeze1Balance` / `freeze2Balance` 做了一张「能量质押 vs 带宽质押」表，
**据此否定了一个正确的假设**（交易迁移到租赁能量），并写下「降价是唯一主因」。

**那两个字段是 Stake 1.0 / Stake 2.0，不是能量/带宽。** 同一条 JSON 里的
`total_energy_weight` / `total_net_weight` 才是。

**发现它的方法很便宜**：**取一个远端历史时点做量级比对。**
2023-12 时 `freeze1` = 316.0 亿而 `total_energy_weight` 只有 62.4 亿——**差 5 倍，不可能是同一个东西。**

> **规则**：**用一个未加文档说明的字段前，先在时间序列的两端各取一点，
> 检查它和同一记录里语义明确的字段是否自洽。**

### ⚠️ 标为「未获取」之前，先真的试一次（TRX 期）

TRX 初稿把「能量租赁的成交量时序」标为 ❌ 未获取，并据此把一处反证降级为「部分验证」。
**实际上它是 DefiLlama 的标准接口，一行 curl 就有**，而且拿到后**直接推翻了那处反证的结论**
（CatFee 月收入 14 个月涨了 28 倍）。

> **「未获取」是一个结论，不是一个默认值。** 写下它之前必须有一次失败的尝试记录。

### ⚠️ 官方治理讨论区是被系统性忽略的一手来源（TRX 期）

TRX 期最关键的数据（能量消耗的月度分项：总量 / 烧币占比 / 质押占比）
来自 **`tronprotocol/tips` 的 Issue #910**——一份官方季度复盘。
它比媒体准，也比官方季报细，**而且它的净供应列与本报告独立计算的序列逐月吻合，可以互相验证。**

**接入新资产时应固定检查协议的治理仓库**（GitHub issues / 论坛 / 提案原文），
不要只看区块浏览器和数据聚合器。**提案原文尤其重要**——
TRX 的提案 #104 原文自己就写明了「会使供应转入通胀趋势」，而所有媒体报道都没提这一句。

### ⚠️ 费用口径的第三个坑：blob ≠ L2 的全部 L1 支出

ADA 期学到 `summary/fees`（L1 链费）≠ `overview/fees`（生态合计）。**ETH 期又多一层**：

**blob base fee 销毁 ≠ L2 支付给 L1 的总额。** L2 还通过 blob 交易的执行费与优先费、
calldata、状态提交、证明验证等路径付费。**L2BEAT 与 Dune 提供完整分解，但两者 API 均需付费密钥。**

**另注意**：**Polygon PoS 按其官方文档是 sidechain，不是 rollup**，做 L2 对照时不应计入。

| # | 要求 | 反例 |
|---|------|------|
| 1 | **门槛必须够得着** | SOL 的「验证者回升至 1,100」，而已披露数列是 791→906 |
| 2 | **论点必须是预测，不是定义** | 「ADA 是期权型资产」是框架选择，无法被世界证伪，不予登记 |

| **5** | **证伪区间必须覆盖论点为假的全部情形，不留与论点方向相反的灰区**（BNB 期新增） | BNB 的 B8-2 论点是「回购收益率会继续递减」，证伪线设在「≥$10.20 亿」。**若下次销毁 $10.19 亿（相对上次上升 9.3%）仍记 ✅——论点被事实反向证明时却判为正确。** 前四条门槛防的是「永远判不了错」，**第 5 条防的是镜像形态：「已经错了却仍判对」** |

| **9** | **论点不得依赖一个本报告已知取不到的数据源**（XIN 期新增） | XIN 期最想登记的论点是「债务余额会被披露」，**而报告自己已确认该数据链上检索返回空、官方披露页已下线**。**一个连观测手段都不存在的论点，写进去只会变成永远的「待验」——那和不登记没区别，却制造了「已在跟踪」的假象** |

### ⚠️ 修订传导清单（SOL 首期踩过的坑）

**审查改完正文后必须回扫，否则会制造比原错误更糟的自相矛盾。**

SOL 首期就是这样：Codex 的三处更正只改了正文，摘要、多空表、监控指标全留在旧版本上，
结果同一份文件里出现十余处互相打架——**而只读摘要的人拿到的恰恰是已被正文推翻的版本**。

改动任何一个正文结论后，强制回扫这五个位置：

```
正文结论改动 → ① 核心结论摘要表 → ② 6.1/6.2 多空评分（含星级）
             → ③ 第 8 章催化剂日历 → ④ 10.3 监控指标 / 10.5 长期认知
             → ⑤ thesis_scorecard.md 的检验条件
```

特别注意 ⑤：**改了正文的判断，检验条件往往就失效了。**
SOL 的 S8-2 原本用「全网中断」做证伪条件，而 3.4 修订后恰恰论证了 8/12 那类事件不算全网中断——
等于承诺这条论点无法被自己识别出的风险推翻。

**记分卡的全部价值来自「能判错」。** 检验条件要能被现实触发，
门槛设得够不着（如「验证者回升至 1,100」，而已披露数列是 791→906）等于自我豁免。

### 审查救不了的一类问题

**来源偏向修不了。** 数据大量来自生态内部来源（Helius、Solana Compass、Cointelegraph 等）时，
审推理不会发现，Codex 也未必。**唯一解法是抓数据阶段就主动找空方来源**——这是写作纪律，不是审查能补的。

## 三个坑（已在脚本里根治，别自己绕回去）

### ① 中文标题的锚点是拼音 slug
Python markdown 把「4. 上市公司比特币储备」转成 `id="4-7"`、「5. AI 科技对 BTC 的多维影响」转成 `id="5-ai-btc"`。**凭空猜必然点不动导航。** 脚本改为从生成的 HTML 里自动抽取 h2 的真实 id，不再手工映射。

### ② 两份 Markdown 合并会撞锚点
完整报告和简明总结各自编号，都可能生成 `id="_1"`。合成一页后点第二个会跳到第一个。脚本给总结的所有标题 id 加 `s-` 前缀隔离，并在自检里检测重复。

### ③ 布局两件事
- **桌面端正文不能设窄的固定 max-width**。曾经设 900px，结果窗口拉大后右侧一大片空白。现用 `padding: clamp(40px,5vw,90px)` 流式铺满，只在超宽屏（>1660px）用 1400px 兜底
- **表格必须包 `.tbl` 滚动容器**。专业版表格设了 `min-width:520px`（5-7 列对比矩阵），不包容器在手机上会撑破版面
