# 加密资产月度专业调研报告

支持多资产。构建时用 `--asset` 指定，资产档案登记在 `build.py` 的 `PROFILES` 字典里。

## 资产间的框架差异（SOL 接入时实测得出）

约六成结构可复用，四成必须换：

| BTC 章节 | SOL 对应 |
|---|---|
| 减半周期 | ❌ → **通胀递减与销毁机制**，且 SOL 的通胀**可被治理投票修改** |
| 算力 / 矿工经济 | ❌ PoS 无挖矿 → **质押率与验证者经济** |
| 数字黄金叙事 | ❌ → **高性能应用执行层** |
| AI 多维影响 | ⚠️ 降级并入生态数据 |
| 上市公司储备 | ✅ 保留，SOL 渗透率约为 BTC 一半 |
| — | ➕ **网络稳定性与宕机史** |
| — | ➕ **生态数据**（TVL / DEX / 稳定币 / RWA） |
| — | ➕ **治理投票** |
| — | ➕ **与 ETH 的 L1 竞争** |

**最根本的差异**：BTC 是货币资产，估值锚是稀缺性；SOL 是**生产性资产**，估值锚应是**网络收入**。
因此 SOL 的情景推导用「假设年化收入 × 假设收入倍数」，而非 BTC 用的「已实现价格 × MVRV」。
接入新资产时先问：**它靠什么产生价值？** 答案决定第 9 章的推导方法。

## 第 1 步：抓数据

用 WebSearch 覆盖这 7 类。**不要凭记忆写数字**——每个月都变，写错就是硬伤。

1. **价格与市场**：现价、距 ATH 回撤、市值、关键支撑阻力、恐惧贪婪指数
2. **ETF 资金流**：当月净流入/出、YTD 累计、总 AUM、IBIT / FBTC 分项
3. **宏观**：美联储主席立场与利率路径、CPI / PCE、10 年美债、DXY、油价、黄金、标普
4. **链上**：MVRV、MVRV Z-Score、STH-MVRV、SOPR、LTH-SOPR、已实现价格、LTH 已实现价格、交易所余额、Puell Multiple
5. **上市公司储备**：总持仓、Strategy / Metaplanet / MARA 等头部动向、**有没有人在卖**、mNAV
6. **监管**：CLARITY 法案进度与通过概率、SBR / ARMA、各国政策
7. **AI 相关**：矿工转 AI/HPC、AI Agent 支付（x402 / L402 / 闪电网络）、量子威胁、AI 诈骗

搜索时把年月写进 query（如 `Bitcoin ETF flows August 2026`），否则容易搜到旧数据。

## 第 2 步：写完整报告（11 章）

框架固定，逐月只换数据和判断：

| 章 | 内容 | 逐月要更新什么 |
|---|------|--------------|
| 0 | 核心结论摘要（一页速览表） | 全部 |
| 1 | 起源与历史背景 | 基本不动 |
| 2 | 发展阶段划分（五阶段） | 只在阶段五追加当月大事 |
| 3 | 当前现状（资产属性 / 市场结构 / 链上 / 宏观 / 技术生态） | **全部重写** |
| 4 | 上市公司比特币储备 | **全部重写** |
| 5 | AI 科技的多维影响 | 更新进展 |
| 6 | 核心价值逻辑（多头 ★ 评分 / 空头 ★ 评分） | 调整强度评级 |
| 7 | 与其他资产比较（黄金 / 美股 / 美债 / ETH） | 更新表现数据 |
| 8 | 未来 1–5 年关键变量（催化剂日历） | **全部重写** |
| 9 | 三种情景推演 + 主观概率 | 调整概率并说明理由 |
| 10 | 投资与风险启示 | 更新周期判断 |
| 11 | 附录（阶段速查 / 减半对比 / 储备速查 / AI 速查 / 数据来源） | 更新数据行 |

写作要求（_dalin 的明确偏好）：

- **中文**。专有名词保留英文原文但要解释它是什么
- **不写成宣传文**。多空都要给，不确定的地方明说"未验证"
- **重点不是预测价格**，是理解历史、现状、逻辑、可能性
- 表格优先于长段落
- 报告开头的引用块里写明「本版更新要点」——列出相比上一版变了什么
- **给出价格区间必须同时给出推导方式**（见 202608 版 9.4 节的写法）。精确的数字如果没有方法论，就是给主观判断打包装
- **必须纳入非加密原生来源**。Cointelegraph / CoinDesk / KuCoin 这类媒体结构上偏多；固定引一节传统机构观点（Deutsche Bank、Citi、JPMorgan 等）配平
- 附录的来源表要标注**核实状态**：哪些是一手抓取，哪些只是搜索摘要，哪些没核实成
- 情景概率变动要说明原因（如"悲观概率上调，因 Strategy 开始抛售"）

## 第 2.5 步：出图表

每期至少三张，放 `btc/professional/charts/`，命名 `<主题>-<YYYYMM>.svg`，在 Markdown 里用相对路径引用：

```markdown
![2026 年 5–8 月 ETF 月度净流量](charts/etf-flows-202608.svg)
```

**为什么用独立 SVG 文件而不是内联**：GitHub 的 Markdown 渲染器会剥掉内联 `<svg>`，但能正常显示 `![](x.svg)` 引用的图片。独立文件同时满足 GitHub 预览、HTML 构建、PDF 渲染三处。

固定的三张：

| 图 | 内容 | 形式 |
|---|------|------|
| ETF 月度净流量 | 近 4 个月净流入/出 | 柱状图，零轴上下分色 |
| 持有者成本基准 vs 现价 | STH / LTH 成本、已实现价格 | 横向条形 |
| 三情景价格区间 | 概率 + 区间 | 横向区间条 |

## 第 4.5 步：更新论点记分卡

`btc/professional/thesis_scorecard.md` 是**跨期滚动**的，每期必做两件事：

1. **核对上期登记的论点**，填入结果与判定（✅ 正确 / ⚠️ 部分 / ❌ 错误）
2. **登记本期新论点**，每条必须写明**可证伪的检验条件**——不可证伪的论断不予登记

然后更新"累计战绩"表，并检查"反复出现的错误模式"一节是否需要新增条目。

> 这一步不能省。报告每月重写一遍很容易，但**不检查上月说对了没有，就只是每月一次的情绪复读**。
> 截至 2026-08，已检验的 8 个论点里只说对了 1 个——这个数字必须公开挂着。

## 第 4.8 步：四层审查（发布前必做，不可跳过）

**背景**：截至 2026-08，BTC 记分卡显示自查过的论点只有 1/8 说对；SOL 首期图表里出现过一个编造的数字，
靠人工渲染检查才偶然发现。**写稿和检查是同一个人做，盲区是同一个。**

```
写稿 → ① 脚本核查 → ② _bian 审推理 → ③ Codex 审领域 → ④ _dalin 抽查 → 发布
```

### 第 1 层：机械核查（脚本，必须先过）

```bash
python3 tools/verify_report.py <asset> <YYYYMM>
```

有 FAIL 就退出非零，**不得进入下一层**。它检查六项：

| 检查 | 抓什么 |
|---|---|
| **图表数字溯源** | 图里显示了正文没有的数字 —— **最重要，编造数据必然在此暴露** |
| 来源核实状态表 | 附录是否标明哪些一手抓取、哪些只是摘要 |
| 来源偏向 | 是否引用了传统机构配平加密原生媒体的看多倾向 |
| 价格区间方法论 | 给了区间是否附推导与弱点 |
| 记分卡登记 | 本期论点是否登记、是否写了可证伪条件 |
| 数据新鲜度 | 是否大量引用过期年份 |

> 实测有效：脚本上线当天就在**已发布的** BTC 8 月版里抓到两处——
> 图表显示的成本基准 $81,821/$59,506 正文里没有，以及图表标 +1.7 而正文写 +1.72。

### 第 2 层：`_bian` 审推理（全局 agent）

把成稿交给 `_bian`，它判推理不判事实。重点让它审：

- 三情景的概率赋值凭什么
- 估值倍数/增速假设的依据够不够
- 有没有把「结构性脆弱」写成「即将断裂」（这是记分卡里出现 3 次的惯犯模式）
- 结论有没有超出证据

### 第 3 层：Codex 审领域

```bash
codex exec --skip-git-repo-check '你是加密资产研究的领域怀疑者。读 <path> 这份报告，
只回答一个问题：它最可能错在哪？给三条，按严重程度排序，直接指出，不要复述内容。'
```

### 第 4 层：_dalin 抽查

只需查 **3–5 个「错了会改变决策」的数字**。脚本末尾会列出大数清单供挑选。
例：SOL 那期是收入 –87%、质押率 64%、Upexi –96%。

### ⚠️ 修订传导清单（SOL 首期踩过的坑）

**审查改完正文后必须回扫，否则会制造比原错误更糟的自相矛盾。**

SOL 首期就是这样：Codex 的三处更正只改了正文，摘要、多空表、监控指标全留在旧版本上，
结果同一份文件里出现十余处互相打架——**而只读摘要的人拿到的恰恰是已被正文推翻的版本**。

改动任何一个正文结论后，强制回扫这五个位置：

```
正文结论改动 → ① 核心结论摘要表 → ② 6.1/6.2 多空评分（含星级）
             → ③ 第 8 章催化剂日历 → ④ 10.3 监控指标 / 10.5 长期认知
             → ⑤ thesis_scorecard.md 的检验条件
```

特别注意 ⑤：**改了正文的判断，检验条件往往就失效了。**
SOL 的 S8-2 原本用「全网中断」做证伪条件，而 3.4 修订后恰恰论证了 8/12 那类事件不算全网中断——
等于承诺这条论点无法被自己识别出的风险推翻。

**记分卡的全部价值来自「能判错」。** 检验条件要能被现实触发，
门槛设得够不着（如「验证者回升至 1,100」，而已披露数列是 791→906）等于自我豁免。

### 审查救不了的一类问题

**来源偏向修不了。** 数据大量来自生态内部来源（Helius、Solana Compass、Cointelegraph 等）时，
审推理不会发现，Codex 也未必。**唯一解法是抓数据阶段就主动找空方来源**——这是写作纪律，不是审查能补的。

## 三个坑（已在脚本里根治，别自己绕回去）

### ① 中文标题的锚点是拼音 slug
Python markdown 把「4. 上市公司比特币储备」转成 `id="4-7"`、「5. AI 科技对 BTC 的多维影响」转成 `id="5-ai-btc"`。**凭空猜必然点不动导航。** 脚本改为从生成的 HTML 里自动抽取 h2 的真实 id，不再手工映射。

### ② 两份 Markdown 合并会撞锚点
完整报告和简明总结各自编号，都可能生成 `id="_1"`。合成一页后点第二个会跳到第一个。脚本给总结的所有标题 id 加 `s-` 前缀隔离，并在自检里检测重复。

### ③ 布局两件事
- **桌面端正文不能设窄的固定 max-width**。曾经设 900px，结果窗口拉大后右侧一大片空白。现用 `padding: clamp(40px,5vw,90px)` 流式铺满，只在超宽屏（>1660px）用 1400px 兜底
- **表格必须包 `.tbl` 滚动容器**。专业版表格设了 `min-width:520px`（5-7 列对比矩阵），不包容器在手机上会撑破版面
